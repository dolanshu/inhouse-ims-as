7 个测试与其断言
----------------
1. test_bootstrap_declares_a_row_level_update_and_delete_trigger
   字面量含 `CREATE TRIGGER audit_row_immutable BEFORE UPDATE OR DELETE ON ` 与
   ` FOR EACH ROW EXECUTE FUNCTION `（行级）。
2. test_bootstrap_declares_a_statement_level_truncate_trigger
   字面量含 `CREATE TRIGGER audit_table_immutable BEFORE TRUNCATE ON ` 与
   ` FOR EACH STATEMENT EXECUTE FUNCTION `（语句级）。
3. test_declared_trigger_types_are_row_level_and_statement_level
   按 `pg_trigger.tgtype` 位掩码（row=1 / before=2 / delete=8 / update=16 / truncate=32）在测试内
   自行算出 27 与 34，再断言 `expected_triggers` 字面量中对
   `audit_row_immutable` == 27（row+before+delete+update）、`audit_table_immutable` == 34
   （before+truncate，无 row 位），且两者 `tgenabled == "O"`。
   即：不是抄数字，而是「位掩码算出来必须等于源码里的数字」。
4. test_guard_function_bodies_raise_check_violation
   `_AUDIT_GUARD_FUNCTION_BODIES`（audit_store.py:101-106）两个函数体均含 `RAISE EXCEPTION` 与
   `USING ERRCODE = '23514'`；row 体含 `audit rows are immutable`，truncate 体含
   `audit table is append-only`。
5. test_bootstrap_installs_the_guard_functions_with_the_declared_bodies
   `ensure_schema` 的 `CREATE FUNCTION` 语句确实携带上述两个函数体，且函数以
   `() RETURNS trigger LANGUAGE plpgsql SET search_path = pg_catalog AS $audit_guard$` 声明
   （`SET search_path` 是防 search_path 劫持的既有约束，一并钉住）。
6. test_bootstrap_takes_an_access_exclusive_lock_before_granting
   字面量含 ` IN ACCESS EXCLUSIVE MODE`（audit_store.py:1048）：发权限前先锁表。
7. test_store_exposes_no_mutation_api
   无 `update/delete/truncate/purge/remove/clear/rewrite/modify` 任一属性；且 `PostgresAuditStore`
   对外名字的**全集**恰为
   {append, connection, ensure_schema, list_events, prefix, qualified_sequence, qualified_table,
   schema, sequence, table, validate_runtime_connection} —— 新增任何公开方法都会在这里红。
